Pointers

Java decides for you whether a value is shared. Go makes you say it out loud, every time.

07

A pointer holds the address of a value rather than the value itself. In Go every variable is either a value, Message, or a pointer to one, *Message. That choice is about sharing, not memory management.

☕ Coming from JavaJava is pass-by-value too. It just quietly copies references, so objects always look shared.
Java
Message m1 = new Message();
Message m2 = m1;  // same object
m2.retries = 5;   // m1.retries is 5
Go
m1 := Message{}
m2 := m1        // a full copy
m2.Retries = 5  // m1 is still 0
Go puts sharing in the type. *Message means someone else may be changing this.The why
Rule of thumbChoose for meaning first. Let the profiler tell you when copying costs too much.
Under the hood
Stack or heap? The compiler decides.

Writing &Message{} doesn't mean "allocate on the heap". The compiler's escape analysis moves a value to the heap only if it might outlive the function. Run go build -gcflags=-m to watch it decide.
