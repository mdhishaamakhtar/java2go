## Design Context

### Users

Experienced Java developers (mid-to-senior level) learning Go. Comfortable with OOP, the JVM ecosystem and Java's verbosity. They come to learn, not to be entertained, but a dense wall of text loses them: the guide has to be clear, calm and pleasant to work through, section after section.

### Brand Personality

An engineering manual, written as a field guide. Precise, explanatory, quietly confident: the voice of a senior engineer who draws a diagram on the whiteboard before writing any code.

### Aesthetic Direction

**Field guide layout.** A reading column with a right-hand margin. Asides such as "Coming from Java" and tips sit in the margin beside the block they belong to, so the main column carries only the argument. Every section has a large faint number at the top, at least one captioned figure, and book-style page turns at the bottom. A slim running header replaces the old sidebar: wordmark, current section, "§ current heading", Contents, search and theme.

**Engineering-manual type.** Three faces, three jobs:

| Role                 | Face                    | Notes                                                                                        |
| -------------------- | ----------------------- | -------------------------------------------------------------------------------------------- |
| Headings, labels, UI | Archivo (variable)      | Headings at `font-stretch: 125%` and extra-bold; labels at 112.5% and bold, in sentence case |
| Reading              | Piazzolla (variable)    | Optical sizes on; body at 1.125rem / 1.72                                                    |
| Code                 | Martian Mono (variable) | `font-stretch: 87.5%` so lines stay short; ligatures always off                              |

All three are self-hosted through `@fontsource-variable`. Static WOFF cuts for the social images live in `public/fonts` (see `src/lib/social-image.tsx`). None of these fonts contain `→`, `✓`, `✗` or other symbol glyphs, so draw those with the icon set or the diagram kit's `Mark`. Never rely on font fallback.

**Four themes.** Paper (light), Lamplight, Night ink and Chalkboard (dark). With no stored choice the site follows the system setting (Paper in light mode, Night ink in dark mode), and the reader's pick is stored in `localStorage` and applied before first paint. Social images use Night ink.

**Anti-references:** generic AI docs templates (permanent numbered sidebar, rounded cards, stacked coloured callout boxes); the AI editorial cliché (cream paper + italic display serif + small, widely spaced uppercase mono labels); gamification (mascots, confetti, badges, streaks); glassmorphism; neon on dark; decoration that competes with the code.

### Colour

`src/lib/themes.ts` is the single source of truth: every colour on the site is defined there, and the root layout turns it into CSS custom properties per theme. Never hard-code a colour in a component, a stylesheet or a diagram. `themes.test.ts` checks every text-on-surface pairing for WCAG AA (4.5:1) in every theme, and `bun run check` fails if any regress.

| Token                 | Tailwind                             | Role                                           |
| --------------------- | ------------------------------------ | ---------------------------------------------- |
| `paper`               | `bg-paper`                           | Page background                                |
| `sunk`                | `bg-sunk`                            | Inset surfaces: code, tables, boxed asides     |
| `chip`                | `bg-chip`                            | Inline code, hover fills                       |

### Design Principles

1. **Amber is Java, teal is Go, in every theme.** Use them consistently: labels, comparison halves, diagram panels, social images. Never swap them, and don't use them for anything else.
2. **The code and the diagrams are the product.** The interface frames them and never competes. Code never scrolls sideways and, at full width, never wraps: comparisons span the folio, side by side when both halves fit and Java above Go when they don't, and a code block too long for the text column takes the full width. Nothing breaks out past the folio's edges.
3. **Asides go to the margin, warnings never do.** Placement is automatic (`src/lib/placement.ts`): a short `java`/`tip`/`info` note sits beside the reading-column block before it, and anything else falls back inline. Readers must not be able to skim past a warning.
4. **A diagram must be right before it is pretty.** Each one explains its section's hardest idea, uses only terms the section introduces, and is checked against the section text and the language. Panels stay at most 360 units wide so text is readable on a phone; wide ideas become more panels.
5. **Typographic weight and width are the hierarchy.** Wide and heavy for titles, semi-wide bold for labels, roman serif for reading, condensed mono for code. Italic is reserved for asides such as pull quotes and figure notes; it is never decoration.
6. **Calm, purposeful motion.** Dialog, drawer and popover transitions and a short cross-fade when the theme changes, nothing more. All motion respects `prefers-reduced-motion`.
7. **Prose at reading width.** Reading-column blocks cap at 40rem (about 68 characters). Code, comparisons, tables and figures may use the full width.
